# 333˚ 상품 소싱 리서치 — 자동화 배치 명세서 v1.0

작성일 2026-09-10 · 대상 독자: 리서치 사이트를 구현하는 개발자
기준 데이터: `dataset_v2.json` (meta.updated 2026-09-01) 의 `prod` 파트 120건

## 0. 이 문서의 목적

지금까지 사람(+LLM)이 수동으로 돌리던 **상품 소싱 리서치**를, 매일 자동으로 실행해도
같은 품질의 결과가 나오도록 규칙을 전부 문자로 고정한 명세서다.

배치 1회가 하는 일은 한 문장으로 이렇다.

> **국내에 정식 유통되지 않는 해외 웰니스·리빙 브랜드의 제품을 찾아서, 공식 판매 페이지에서 실제로 가격을 확인하고, 333˚ 리테일에 왜 맞는지를 서술한 레코드를 만들어 기존 배열 뒤에 붙인다.**

핵심은 3가지다. 이 셋 중 하나라도 무너지면 배치를 실패로 처리해야 한다.

1. **검증 없는 항목은 넣지 않는다** — 가격은 반드시 공식 판매 페이지에서 확인한 것이어야 한다
2. **중복을 넣지 않는다** — 이미 조사한 229건 목록(`seen`)을 매 실행마다 입력으로 넘긴다
3. **배열 앞에 끼워 넣지 않는다** — `id`가 배열 순서로 찍히므로, 앞에 삽입하면 기존 판정(fit/hold)이 전부 어긋난다

## 1. 산출물 계약 (Output Contract)

### 1.1 레코드 스키마

`prod` 배열의 원소 1개 = 상품 1개. 전 필드 필수(값이 없으면 `"미확인"`), 단 `wholesale`은 선택.

| 필드 | 타입 | 설명 | 값 규칙 |
|---|---|---|---|
| `id` | string | `p001` 형식. **배치가 만들지 않는다** | 빌드 단계에서 배열 인덱스로 재생성 |
| `v` | string | 사장님 판정 | `''` 미판정 / `'fit'` 적합 / `'hold'` 보류. **배치는 절대 건드리지 않는다** |
| `brand` | string | 브랜드명 (원어 표기 우선) | 예: `Bathing Culture`, `Ippodo Tea (一保堂茶舗)` |
| `product` | string | 제품명 + 용량/수량 | 예: `Mind and Body Wash Refillable Glass (16 fl oz)` |
| `cat` | string | 대분류 | `B` / `F` / `S` / `L` 중 하나 (§2) |
| `sub` | string | 자유 서술 소분류 | 예: `바디워시 · 리필형` — 이 문자열로 `subCode`가 자동 배정됨 |
| `subCode` | string | 자동 배정 | 빌드 단계 생성. 배치가 쓰지 않는다 |
| `subName` | string | 자동 배정 | 빌드 단계 생성 |
| `origin` | string | 원산/본사 소재 | 예: `미국 (샌프란시스코)`, `핀란드` |
| `url` | string | 브랜드 공식 사이트 루트 | https 필수 |
| `priceSrc` | string | **가격을 실제로 읽은 페이지 URL** | 제품 상세 또는 컬렉션 페이지. `url`과 같아도 됨 |
| `price` | string | 원문 통화 + 원화 환산 | 형식 §4.2 |
| `ig` | object | `{handle, url, followers}` | §4.3 |
| `design` | string | 디자인·패키지 서술 2~4문장 | §5.1 |
| `story` | string | 브랜드 서사 2~3문장 | §5.1 |
| `why333` | string | 333˚ 리테일에 맞는 이유 | §5.1 — 여기가 이 리서치의 본체다 |
| `edge` | string | 남들이 못 가진 지점 1~2문장 | §5.1 |
| `krDist` | string | 국내 유통 여부 | 기본값 `"미확인"` (§6) |
| `verified` | string | **무엇을 어디서 확인했는지** 서술 | 비면 안 된다. §4.1 |
| `confidence` | string | `높음` / `중간` / `낮음` | 자동 산출 §4.4 |
| `wholesale` | string | 도매 거래 가능성 | `홀세일 페이지 있음` / `문의 필요` / `미확인` |
| `sources` | array | `[{t: 제목, u: URL}]` | 최소 1개. `priceSrc`가 반드시 포함될 것 |
| `addedOn` | string | `YYYY-MM-DD` | 배치 실행일. **기존 항목은 절대 갱신 금지** |

`addedOn`을 기존 항목에 다시 찍으면 화면의 NEW 배지가 전부 켜지고 "오늘 뭐가 늘었나"를
볼 수 없게 된다. 배치는 **신규 항목에만** 오늘 날짜를 찍는다.

### 1.2 파일 흐름

```
[일일 배치]  → v2_new_prod.json      (오늘 찾은 것만, 원시 형태)
     ↓ merge (§7)
             → v2_prod.json          (누적 마스터, append-only)
     ↓ build_v2.py
             → dataset_v2.json       (id/subCode/cats/seen 생성)
     ↓ build2.py
             → 333-desk.html         (화면)
```

배치가 직접 써야 하는 파일은 **`v2_new_prod.json` 하나뿐**이다. 나머지는 기존 스크립트가 처리한다.

### 1.3 `v2_new_prod.json` 원시 스키마

머지 스크립트가 받는 형태는 최종 스키마와 필드명이 조금 다르다. 이 이름을 그대로 써야 한다.

```json
[
  {
    "brand": "Bathing Culture",
    "name": "Mind and Body Wash Refillable Glass (16 fl oz)",
    "cat": "B",
    "sub": "바디워시 · 리필형",
    "origin": "미국 (샌프란시스코)",
    "url": "https://bathingculture.com/products/16oz-refillable...",
    "price": "$36 (약 5만원)",
    "ig": "bathingculture",
    "design": "...",
    "story": "...",
    "fit": "...",
    "edge": "...",
    "krStatus": "미확인",
    "verified": "공식몰 제품페이지에서 제품명·용량·가격 $36 확인",
    "wholesale": "홀세일 페이지 있음",
    "sources": [{"t": "Bathing Culture 제품페이지", "u": "https://..."}]
  }
]
```

매핑: `name`→`product`, `fit`→`why333`, `krStatus`→`krDist`, `url`→`url`·`priceSrc` 양쪽.

## 2. 카테고리 체계

대분류 4개. **시간축**으로 나눈다 — 회원이 사우나에서 나온 뒤 흘러가는 순서다.
상품 속성으로 나누지 않는다는 것이 설계 원칙이었다.

| 코드 | 이름 | 축 | 현재 건수 |
|---|---|---|---|
| `B` | 뷰티 | 열이 빠지는 30분 | 24 |
| `F` | 식품 | 다시 채우는 것 | 33 |
| `S` | 건기식 | 회복의 과학 | 14 |
| `L` | 생활용품 | 집으로 가져가는 333˚ | 33 |

소분류는 **배치가 지정하지 않는다.** `sub` 자유 서술 문자열에 정규식을 걸어
`build_v2.py`가 자동 배정한다. 아래가 그 규칙표이며, **위에서부터 첫 매칭**이 배정된다.

```python
RULES = {
```

매칭되지 않으면 `B9` `F9` `S9` `L9` = **기타**로 떨어진다.

> **개발자 주의** — 기타 비율이 배치별로 15%를 넘으면 알림을 띄우게 하라.
> `sub` 서술이 규칙표에서 벗어나고 있다는 신호이고, 그때는 규칙표에 항목을 추가해야 한다.
> 규칙표를 늘릴 때는 **기존 코드의 정규식을 바꾸지 말고 새 코드를 뒤에 추가**한다
> (기존 항목의 subCode가 바뀌면 화면 그룹이 흔들린다).

## 3. 소싱 기준 — 무엇을 넣고 무엇을 버리는가

### 3.1 포함 3원칙

1. **서사 밀도** — 명인·무형유산·단일 산지·발효 기간처럼 **숫자와 이름으로 설명되는 근거**가 있을 것
2. **감각의 연속성** — 열린 모공, 미네랄 손실, 이완된 신경계라는 사우나 직후 신체 상태와 제품 효용이 자연스럽게 이어질 것
3. **PB 전환 가능성** — 소량 다품종 생산이 가능해서 2단계에서 `333˚ Edition`으로 재해석할 여지가 있을 것

### 3.2 배제 규칙 (하나라도 걸리면 버린다)

| 배제 사유 | 판정 방법 |
|---|---|
| **국내 대형 유통 브랜드** | 올리브영·쿠팡·마트·드럭스토어 정식 입점 브랜드. *40만원 멤버십 리테일에 락토핏이 놓이는 순간 큐레이션 신뢰가 무너진다* |
| **가격 확인 불가** | 공식몰에 가격이 없거나 JS 위젯 뒤에 숨어 못 읽은 경우 → 버리거나 `confidence: 낮음`으로 격리 |
| **브랜드 4종째** | 같은 브랜드는 **최대 3 SKU**. 4번째부터 자동 제외 (§7.2) |
| **이미 조사됨** | `seen` 목록의 brand+product 조합과 일치 |
| **공식몰 부재** | 리셀러·아마존에서만 파는 브랜드는 도매 협상 경로가 없다 |
| **국내 정식 총판 존재** | "여기서만 살 수 있는 것"이라는 리테일 전제가 깨진다 |

### 3.3 우선 탐색 축

현재 수집분의 지역 분포는 핀란드 18 · 영국 16 · 미국 15 · 덴마크 11 · 일본 8 순이다.
탐색이 매일 같은 곳만 도는 것을 막기 위해 **축을 로테이션**한다.

- 지역: 북유럽(FI/SE/DK/NO) / 영국·아일랜드 / 미국 서부 / 미국 동부 / 일본 / 독일·오스트리아·스위스 / 프랑스·이탈리아 / 대만·홍콩·싱가포르
- 채널: 사우나·배스하우스 공식몰의 리테일 코너 / 편집숍(Goods We Love, The Bathing Shop 류) 취급 브랜드 / 홀세일 플랫폼(Faire) 카테고리 / 디자인 어워드 수상 목록
- 카테고리: 현재 얇은 곳부터 — `S`(14건) → `B`(24건) → `F`·`L`(33건)

배치 설계 제안: **하루 1축 × 신규 목표 8~15건.** 이 페이스면 카테고리별 편중 없이 한 달에 약 250~450건이 쌓인다.

## 4. 검증 규칙 — 여기가 품질의 전부다

### 4.1 `verified` 필드

**이 필드가 비어 있으면 레코드를 버린다.** "어디서 무엇을 확인했는지"를 문장으로 남긴다.

좋은 예:
> `공식몰 제품페이지에서 제품명·용량·가격 $36 확인, 컬렉션 페이지에서 전 라인 가격 확인, 공식몰 IG 링크 확인`

나쁜 예: `확인함`, `공식 사이트 참조`, 빈 문자열

검증 대상 최소 3개: **① 제품명 ② 가격(통화·금액) ③ 용량 또는 수량.**

### 4.2 `price` 형식

```
<원문 통화 금액> (약 <원화 만원 단위>만원)
```

- 정상: `$36 (약 5만원)` · `€15 (약 2.4만원)` · `£18.00 정가 (현재 20% 할인가 £14.40) (약 3.3만원)`
- 할인 중이면 **정가와 현재가를 둘 다** 적고, 원화 환산은 **정가 기준**으로 한다
- 세트/멀티팩은 개당이 아니라 판매 단위 그대로 적는다

**환율표 (2026-08 기준, 배치 설정값으로 분리할 것)**

| 통화 | 원 | 통화 | 원 | 통화 | 원 |
|---|---|---|---|---|---|
| USD | 1,381 | GBP | 1,850 | EUR | 1,600 |
| JPY | 9.5 | CAD | 1,010 | AUD | 910 |
| CHF | 1,730 | SEK | 145 | DKK | 215 |
| NOK | 137 | SGD | 1,078 | HKD | 177 |
| TWD | 44 | THB | 43 | MYR | 330 |
| PHP | 24 | VND | 0.054 | IDR | 0.085 |
| NZD | 815 | | | | |

> 환율은 **하드코딩하지 말고 설정 파일로 뺀다.** 다만 갱신하면 과거 항목의 원화 표기와
> 어긋나므로, 갱신 시점을 `meta.fxDate`로 남기고 과거 항목은 재계산하지 않는다.

### 4.3 `ig` 정규화

```python
def ig_obj(v):
    if not v or str(v).lower() in ('null', 'none', '미확인'):
        return {'handle': '미확인', 'url': '', 'followers': '미확인'}
    h = v if str(v).startswith('@') else '@' + str(v)
    return {'handle': h, 'url': 'https://instagram.com/' + h.lstrip('@'), 'followers': '미확인'}
```

핸들은 **공식 사이트 푸터/헤더에서 확인한 것만** 넣는다. 검색으로 추정한 핸들은 `미확인`.
`followers`는 인스타그램이 비로그인 크롤링을 막아 현재 전량 `미확인`이다 — 채우려 하지 말 것.

### 4.4 `confidence` 자동 산출

```python
confidence = '낮음' if ('미확인' in price or '3자' in price) else '높음'
```

즉 **가격 출처가 공식몰이면 높음, 미확인이거나 제3자 사이트면 낮음.**
현재 분포는 높음 115 · 중간 5 (`중간`은 수동 하향 조정분이다 — 배치는 자동으로 부여하지 않는다).

## 5. 서술 필드 작성 규칙

### 5.1 4개 서술 필드의 역할 분담

겹쳐 쓰면 화면에서 같은 말이 네 번 반복된다. 각자 답하는 질문이 다르다.

| 필드 | 답하는 질문 | 길이 | 금지 |
|---|---|---|---|
| `design` | **눈에 어떻게 보이는가** — 패키지 형태·색·타이포·소재 | 2~4문장 | 효능 이야기 |
| `story` | **브랜드가 어디서 왔는가** — 창립 연도, 지역, 생산 방식, 인증 | 2~3문장 | 마케팅 형용사 |
| `why333` | **333˚ 공간에서 어떤 동작에 붙는가** — 세션 흐름 중 어느 지점, 어떤 가격대 역할 | 2~4문장 | 일반적 좋은 말 |
| `edge` | **남들이 못 가진 것** — 구조적 우위 1가지 | 1~2문장 | 반복 |

`why333` 좋은 예:
> 사우나 세션의 마지막 동작이 바디워시다. 매장 샤워실에 5갤런 페일을 걸어 쓰고 같은 제품의
> 16oz 유리병을 리테일로 파는 '체험→구매' 구조가 그대로 성립한다.

— **공간의 특정 동작**에 상품을 붙였고, **운영 소모품과 판매 상품을 통일**한다는 구조를 말했다.
"고급스럽고 사우나와 잘 어울린다" 같은 문장은 이 필드의 실패다.

### 5.2 문체

- 평서형 종결. 존댓말과 반말을 섞지 않는다 (현행 데이터는 `~다` 체가 주류이나 일부 `~습니다` 혼재 — **`~다` 체로 통일**하는 것을 권장)
- 브랜드명·제품명은 원어 그대로. 한글 음차를 병기하지 않는다
- 숫자는 원문 단위 그대로 (16 fl oz, 23cl, 250g)

## 6. `krDist` — 국내 유통 검증 (미구현, 별도 배치 권장)

현재 120건 중 **91건이 `미확인`이다.** 이것이 이 리서치의 가장 큰 구멍이다.
"국내 미유통"이 소싱의 전제인데 정작 그 전제를 검증하지 않았다.

**별도 배치로 분리할 것을 권한다.** 브랜드명(원어 + 한글 음차)으로 다음을 순회 검색:

```
올리브영 / 29CM / 무신사 / 쿠팡 / SSG / 컬리 / 네이버쇼핑 / 발란·머스트잇
```

판정 결과를 3값으로 고정:

| 값 | 의미 | 후속 |
|---|---|---|
| `국내 정식 유통 확인` | 총판·공식 입점 존재 | **소싱 후보에서 제외** — `v: 'hold'` 자동 부여 검토 |
| `병행수입만 확인` | 리셀러 판매만 존재 | 유지. 정식 총판 협상 여지 있음 |
| `국내 유통 없음` | 검색 결과 없음 | 유지. 최우선 소싱 후보 |

검색일자를 `krCheckedOn`으로 함께 남긴다. 유통 상황은 바뀌므로 **90일 지나면 재검증 대상**으로 표시.

## 7. 중복 제거 및 병합 (실제 동작 코드)

### 7.1 정규화 함수

```python
import re, unicodedata

def norm(s):
    return re.sub(r'[^a-z0-9가-힣ぁ-んァ-ヶ一-龯]', '',
                  unicodedata.normalize('NFKC', str(s or '')).lower())
```

NFKC 정규화 후 영문 소문자화, 한글·히라가나·가타카나·한자만 남기고 전부 제거.
`Ippodo Tea (一保堂茶舗)` → `ippodotea一保堂茶舗`

### 7.2 병합 규칙

```python
prod = load('v2_prod.json')
pair = {(norm(p['brand']), norm(p['product'])) for p in prod}
bn   = {}
for p in prod:
    bn[norm(p['brand'])] = bn.get(norm(p['brand']), 0) + 1

for e in load('v2_new_prod.json'):
    b, n = norm(e['brand']), norm(e['name'])
    if (b, n) in pair:
        log('중복 제외: ' + e['brand'] + ' ' + e['name']);  continue
    if bn.get(b, 0) >= 3:
        log('브랜드 3종 초과: ' + e['brand'] + ' ' + e['name']);  continue
    price = e.get('price') or '미확인'
    prod.append({
        'brand': e['brand'], 'product': e['name'], 'cat': e['cat'], 'sub': e['sub'],
        'origin': e['origin'], 'url': e['url'], 'priceSrc': e['url'], 'price': price,
        'ig': ig_obj(e.get('ig')),
        'design': e.get('design',''), 'story': e.get('story',''),
        'why333': e.get('fit',''),   'edge': e.get('edge',''),
        'krDist': e.get('krStatus','미확인'),
        'verified': e.get('verified',''), 'wholesale': e.get('wholesale','미확인'),
        'confidence': '낮음' if ('미확인' in price or '3자' in price) else '높음',
        'sources': e.get('sources', []),
        'addedOn': TODAY,
    })
    pair.add((b, n));  bn[b] = bn.get(b, 0) + 1
```

**두 가지가 절대 규칙이다.**

- `prod.append(...)` — **반드시 append.** `insert(0, ...)`나 정렬은 금지.
  `id`가 배열 인덱스로 찍히므로 순서가 바뀌면 사장님이 화면에서 누른 `fit`/`hold` 판정이
  다른 상품으로 옮겨 간다. 데이터 손상이고 복구가 어렵다.
- 기존 원소의 `addedOn`·`v`는 읽기만 한다.

### 7.3 `seen` 레지스트리

배치는 **실행 전에 `dataset_v2.json`의 `seen` 배열을 읽어 LLM 프롬프트에 넘겨야 한다.**
현재 229건이며 상품 파트는 이렇게 만들어진다.

```python
for p in prod:
    seen.append({'part':'상품', 'name': p['brand'] + ' — ' + p['product'],
                 'url': p.get('url'), 'note': p.get('origin','')})
```

이걸 넘기지 않으면 같은 브랜드를 매일 다시 찾아온다. 실제로 겪은 문제다.

## 9. 품질 게이트 — 배치 성공 판정

배치 종료 시 아래를 **자동 검사**하고, 하나라도 실패하면 머지를 롤백한다.

| # | 검사 | 실패 조건 |
|---|---|---|
| 1 | 필수 필드 존재 | `brand` `product` `cat` `url` `price` `verified` 중 빈 값 |
| 2 | `cat` 유효성 | `B/F/S/L` 이외 값 |
| 3 | `verified` 실질성 | 15자 미만이거나 `확인함` 류 상투어만 |
| 4 | `sources` | 배열이 비었거나 `priceSrc` URL이 포함되지 않음 |
| 5 | 가격 형식 | `(약 N만원)` 패턴 부재 |
| 6 | URL 도달성 | HTTP 200이 아닌 `url` / `priceSrc` |
| 7 | **id 안정성** | 빌드 후 기존 항목의 `id`↔`brand+product` 매핑이 이전 스냅샷과 다름 → **최우선 차단** |
| 8 | 판정 보존 | 기존 항목의 `v` 값이 변경됨 |
| 9 | `addedOn` 오염 | 기존 항목의 `addedOn`이 오늘로 바뀜 |
| 10 | 기타 비율 | 신규분 중 `subCode`가 `?9`인 비율 > 15% (경고) |
| 11 | 중복률 | 신규 후보 중 `seen` 중복 비율 > 60% (경고 — 탐색 축이 고갈됨) |
| 12 | 회귀 시험 | `python test_fee.py` 27건 통과 (회비 파서 — 상품 배치가 건드릴 일은 없지만 빌드 공유) |

### 9.1 id 안정성 검사 구현

```python
# 배치 전 스냅샷
before = {p['id']: (norm(p['brand']), norm(p['product'])) for p in old_dataset['prod']}
# 배치 후
after  = {p['id']: (norm(p['brand']), norm(p['product'])) for p in new_dataset['prod']}
for pid, key in before.items():
    assert after.get(pid) == key, f'id 오염: {pid} 가 {key} → {after.get(pid)} 로 바뀜'
```

이 검사 하나가 이 시스템에서 가장 중요하다. 사장님의 판정 데이터를 지키는 유일한 방어선이다.
